# Parcel Sorter ROCm 技术报告

## 1. 项目摘要

Parcel Sorter ROCm 是一套在单张 AMD Radeon GPU 上运行的小快递抓取与双格口分拣
Physical AI 系统。项目面向小型仓储工位：快递的尺寸、质量、摩擦、位置和朝向会变化，
机器人需要抓取、抬升、搬运、释放并验证落格，同时不突破接触力安全边界。

系统使用 Genesis 刚体物理和渲染、Franka Panda、RGB-D 与本体状态、IK 专家、确定性
安全监督器、LeRobotDataset 和 ACT 视觉模仿策略。物理、数据采集、训练、推理和性能
测试均已在单张 `gfx1100` Radeon 与 ROCm 7.2.1 上执行。

## 2. 应用定义与价值

小型履约工位、教学和个人机器人研发需要一种不依赖大量真机与数据中心 GPU 的操作
开发流程。本项目构建一个紧凑分拣站：机械臂在限定工作区抓取随机包裹，根据目标将其
放入左右格口。该任务同时覆盖感知、运动、接触、恢复和安全，而且适合在单张桌面级
Radeon 上复现。

系统可用于控制器预部署验证、合成演示数据生成、机器人教学和低吞吐快递操作研究。

## 3. 系统架构

系统分为五层：

1. **仿真与传感：**Genesis 以 240 Hz 运行物理、30 Hz 控制、10 Hz 相机。
2. **任务监督：**检测、接近、抓取、验证、抬升、放置、释放、完成和中止状态机。
3. **动作生成：**脚本 IK 专家或 ACT/Diffusion/SmolVLA 输出高层末端目标与夹爪命令。
4. **低层执行：**末端步长限制、IK、机械臂 PD、夹爪力斜坡和接触力边界。
5. **证据评估：**JSONL、LeRobotDataset、MP4、运行环境、任务指标与性能数据。

学习模型不替代安全监督器。专家和 ACT 共用同一动作契约、IK、控制与硬安全边界。

## 4. 物理环境与机器人

Genesis 1.2.3 提供 AMD GPU 物理和离屏渲染。Franka Panda 使用 Genesis 提供的 MJCF
资产。每个 episode 生成一个刚体包裹，并随机分配左右格口。

目录配置定义 7 类带权训练包裹：微型盒、小纸箱、扁盒、长盒、直立罐、横向邮筒和
近夹爪极限盒；另有 4 类行业尺寸只用于能力边界评测。Genesis 根据 profile 创建 Box 或
Cylinder，而不是把圆筒伪装成盒子。每 20 回合精确分配训练权重，profile 定点评测使用
稳定 episode 编号。

| 参数 | 数值 |
| --- | ---: |
| 物理频率 | 240 Hz |
| 控制频率 | 30 Hz |
| 相机频率 | 10 Hz |
| 图像分辨率 | 224 x 224 |
| 回合上限 | 20 s |
| 自由空间末端步长 | 0.04 m |
| 最终接近步长 | 0.01 m |
| 夹爪闭合力 | 20 N，1 N/step 斜坡 |
| 接触力安全阈值 | 35 N |
| 最大抓取重试 | 2 |

域随机化覆盖包裹尺度、质量、摩擦、XY、yaw、相机位置、动作延迟和目标。每个场景由
项目 seed 与 episode 索引唯一决定，因此失败可以精确重放。

## 5. 感知与动作契约

模拟器输出 RGB、米制深度、9 维关节位置、7 维末端位姿、3 维目标位置、夹爪接触力
和 7 维包裹位姿。ACT 的 20 维状态只包含机器人、目标和接触力；包裹真值作为特权审计
状态保留，不输入 ACT。

学习动作是 8 维：末端位置、目标四元数和夹爪命令。执行前会检查形状与有限数、归一化
四元数、限制末端位移，并由状态机确定夹爪语义，防止异常策略输出绕过安全。

## 6. 专家与闭环控制

专家使用包裹对齐的顶抓，并分为升至安全高度、水平移动和最终下降。抓取后验证双指
接触，再抬升、移动、释放并检查包裹是否位于目标格口。

监督器能够等待接触稳定、重试抓取、检测短时接触丢失、验证释放，并在接触力过大或
仿真故障时中止。目录控制器将水平接近和最终位姿容差分离，在水平对齐后锁定 0.01 m
下降，按几何调整预抓取窗口，并采用竖直抬升、水平搬运、竖直下降的安全路径。

这不等于早先被拒绝的“只把全局最终步长改成 0.01 m”候选；后者缺少 XY 门控、滞回和
几何窗口，在同组 120 回合中从 80% 退化到 75%。

## 7. 数据与学习策略

正式采集包含 120 个随机回合。96 个成功回合写入 LeRobotDataset，共 11,753 帧 RGB-D；
全部失败和成功均保留 JSONL 审计轨迹。数据完全由仿真自建，不包含个人数据。

ACT 为 52M 参数，action chunk 30，执行 10 个 action step。正式训练使用 batch 32、AMP、
5000 步、10% 评估切分和周期检查点。深度已保存在数据中，但当前 ACT 基线只输入 RGB
和 20 维状态。训练脚本现将通用图像增强默认关闭，并提供开关做严格消融。已记录的
5000 步结果使用修改前的“增强开启”设置，因此仍作为对照基线，不能归因于新默认值。

项目同时提供 Diffusion 和 SmolVLA 的 Radeon 训练入口。Diffusion 用作常规模仿学习
对照，已完成 1 步训练链路烟雾；SmolVLA 从本地传入的开源 `lerobot/smolvla_base`
微调，首轮冻结视觉编码器。两者尚无正式能力结果，因此不计入当前任务数据。通用适配器会从检查点
识别策略类型，并将三种策略放入同一个监督器、IK/PD 和 35 N 安全链路。

## 8. AMD Radeon 与 ROCm 使用

项目在 GPU 工作前检查 `torch.version.hip`、设备数量、GPU 名称和显存。Genesis 使用
`gs.amdgpu`，ACT 通过 PyTorch ROCm 执行。单张 GPU 同时承担：

- Genesis 物理 kernel 编译与步进；
- RGB-D 离屏渲染；
- ACT 前向、反向和混合精度训练；
- 检查点加载与实时推理；
- 并行仿真吞吐测试。

PyTorch ROCm 继续使用 `torch.cuda` 兼容接口，因此源码中的 `cuda:0` 在 Radeon 路径表示
HIP 设备。运行证据同时记录 HIP 版本和 GPU 名称，避免误报 CUDA 结果。

## 9. 评估方法

任务成功要求包裹释放在指定格口。次级指标包括首次成功率、恢复率、掉落率、完成时间、
成功件/小时、接触力、平均推理延迟与 P95 延迟。每个输出均保存配置、运行环境、episode
参数、终止状态和聚合指标。

ACT 使用确定且不重叠的 episode 范围评估。检查点汇总工具会拒绝重复 episode，并优先
按闭环成功率、掉落率、P95 延迟和接触力排序，而不是按离线 loss 选最终模型。

## 10. 已验证结果

| 实验 | 结果 |
| --- | ---: |
| 正式随机专家 | 96/120 成功，80.0% |
| 首次专家成功率 | 77.5% |
| 有重试回合中的恢复成功率 | 37.5% |
| 成功训练数据 | 96 回合，11,753 帧 |
| 固定 10 种子专家 | 90.0%，掉落率 0% |
| 固定种子吞吐 | 727 成功件/小时 |
| ACT 5000 步最终评估 loss | 0.1384 |
| ACT 4000，episode 10-19 | 成功率 30% |
| ACT 4000 推理平均/P95 | 2.05 ms / 8.00 ms |
| ACT 5000，episode 10-19 | 成功率 10% |
| 被拒绝的 0.01 m 接近候选，同组 120 回合 | 成功率 75.0%，吞吐保留 73.6% |
| 128 并行 Genesis | 46,582 environment-steps/s |
| 峰值 GPU 利用率 | 83% |
| 7 类目录单回合烟雾回归 | 4 类完成；不是正式成功率 |
| 单元测试 | 48 项通过 |

120 回合专家结果是当前主要机器人能力指标。ACT 已证明 ROCm 数据、训练、检查点、重载、
视觉推理和物理闭环跑通，但尚未收敛。4000 步在同一组任务上优于 5000 步，说明最终
模型必须按闭环任务选择。

## 11. 失败分析与限制

正式专家 24 次失败中，22 次触发接触力安全边界，2 次在抬升时丢失抓取，最大观察力约
109.8 N。同组 120 回合上的固定 0.01 m 最终接近候选已被拒绝：成功率从 80.0% 降为
75.0%，力中止从 22 次增加到 25 次，吞吐仅保留 73.6%。下一次控制实验必须结合间距和
接触力反馈做分阶段速度/阻抗整形；提高安全阈值或未经闭环验证的固定减速都不接受。

其他限制：

- ACT 只有 96 个成功训练回合和 5000 步训练；
- 当前策略没有使用已保存的深度；
- 微型盒、直立罐和横向邮筒在最终目录烟雾中仍失败；
- Diffusion 只有 1 步链路烟雾，SmolVLA 尚未获得本地基座；二者均无正式闭环统计；
- 结果为仿真，尚无 sim-to-real 证据；
- Docker 定义可复现，但主要验证路径使用比赛裸机云镜像；
- 当前版本没有宣称已完成上游合并贡献。

## 12. 创新与贡献

项目贡献不是单个模型，而是一条可复现的混合 Physical AI 链路：确定性域随机化、策略
状态与特权状态分离、专家/学习策略共享安全动作契约、失败审计保留、不重叠 episode
检查点选择、多几何包裹目录、几何感知控制，以及单卡 ROCm 仿真—训练—推理全流程。

## 13. 交付物

仓库包含完整原创源码、测试、配置、固定依赖、ROCm 脚本、Dockerfile、训练/评估与
benchmark 工具、中英文说明、原始小体积证据和本报告。生成物包括 JSONL、
LeRobotDataset、ACT 检查点、summary、benchmark、日志和 MP4。

大型数据与权重不直接进入 Git，应在最终提交中通过 release/object storage 提供并附
SHA-256。

## 14. 团队与贡献

当前 Git 版本按单人项目维护。最终 PR 需要填写与 Luma 一致的法定姓名和团队名称。
参与者负责系统设计、仿真/控制、数据、ROCm 训练与 benchmark、评估、失败分析、文档和
演示制作。
