# 复位后备风险门控验证结果

## 实验范围

本轮开发验证在单张 AMD Radeon GPU 与 ROCm 上，对比“碰撞检查复位”和“复位后备风险门控几何
规划”。实验覆盖 12 个当前平行夹爪支持的包裹 profile，每个 profile 使用 5 个严格配对回合；每组
60 回合，共 120 个闭环回合。35 N 力上限、随机样本、profile 分层以及局部回合编号
`120000`--`120004` 均在运行前冻结。预留给最终确认的 `200000`--`200039` 没有被查看。

## 总体结果

| 指标 | 碰撞检查复位 | 风险门控规划 | 候选变化 |
| --- | ---: | ---: | ---: |
| 成功 | 35/60（58.3%） | 33/60（55.0%） | -2 回合 |
| 力中止 | 17/60（28.3%） | 19/60（31.7%） | +2 回合 |
| 掉落 | 0/60 | 0/60 | 0 |
| 逐回合峰值力均值 | 22.87 N | 29.54 N | +6.67 N |
| 逐回合峰值力 P95 | 51.21 N | 69.00 N | +17.78 N |
| 逐回合最大峰值力 | 104.73 N | 233.75 N | +129.02 N |
| 成功吞吐 | 307.42 件/小时 | 279.88 件/小时 | 0.910 倍 |

成功与力中止的精确配对 McNemar p 值均为 0.625。逐回合峰值力的配对均值变化为 +6.67 N，
确定性 10,000 次 Bootstrap 95% 区间为 [-0.53, +16.85] N，配对符号翻转 p 值为 0.163。
这些区间不能建立总体效应，但观察方向已经不满足开发验收规则，没有理由打开预留确认集。

## 门控与归因审计

候选中有 17 个回合使用后备复位，5 个回合满足几何适用条件，5 个回合实际启用规划，门控避免
规划的回合为 0。也就是说，5 个几何适用回合全部同时满足后备复位条件；新门控相对原有几何
适用规则没有节省任何规划工作。5 次规划共消耗 31,965.11 ms，平均每次 6,393.02 ms。

只看 5 个规划实际启用回合，基线成功 3/5，候选成功 2/5。候选恢复 `5120003`，但使
`4120001` 和 `7120004` 回归；该子集的逐回合峰值力均值增加 42.55 N。这个子集只能用于描述，
样本量不足以支持一般化结论。

另一个回归 `5120000` 发生时规划器未启用，规划次数为 0。连续状态在第 104 帧首次分叉，高层
决策在第 121 帧才首次分叉。因此它被保守地归为“执行非确定性候选”，不能算作规划器效果；仍需
通过同条件重复执行直接测量仿真器与 GPU 的方差。

## 工程决策

拒绝把复位后备风险门控规划升级为最终确认方法，功能继续默认关闭。本轮验证中，它既没有减少
规划工作，也没有降低总体安全风险；规划实际启用子集中，回归数还多于恢复数。不得提高 35 N
阈值，也不得查看预留确认回合来挽救假设。

本轮有价值的交付是可复现负结果：完整保留门控机制、严格配对 campaign、因果归因审计以及执行
分叉证据，解释为什么单一困难 profile 上的强结果没有推广到多 profile。下一轮应先量化同条件
执行重复，再选择新的控制干预。

## 复现与完整性

执行命令：

```bash
bash scripts/run_reset_fallback_gate_campaign_rocm.sh
```

`paper-evaluation.json` 保存 Wilson 区间、精确 McNemar、配对 Bootstrap、符号翻转检验和 profile
分层；`gate-attribution-audit.json` 分开记录规划启用与未启用的结果变化。
`COMPACT-SHA256SUMS` 已在本地和 Radeon 主机验证通过。`REMOTE-SUMMARY-SHA256SUMS` 保存两份
20 MB 以上完整逐帧源 summary 的哈希，原始文件继续保留在 Radeon 工作区。
