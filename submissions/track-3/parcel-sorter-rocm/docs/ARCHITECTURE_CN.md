# 中文架构与实验计划

## 完整闭环

```text
Genesis 场景和 Franka
  -> RGB-D、关节、末端位姿、夹爪接触力
  -> 真值专家或后续 ACT/VLA 策略
  -> 绝对末端位姿与夹爪命令
  -> 动作限幅、IK、PD 和力控制
  -> 机器人与快递发生物理交互
  -> 接触验证、抬升验证、失败重试、释放验证或安全中止
  -> JSONL/LeRobotDataset、MP4 和评估指标
```

学习模型不会直接输出关节力矩。模型输出统一收敛到 `CartesianAction`：目标位置、目标四元数和夹爪开合。IK、PD、力限制、重试和安全中止始终保留在模型外部，这使 ACT、行为克隆和轻量 VLA 可以复用同一执行链。

## 六项能力映射

| 方向 | 当前实现 | 最终证据 |
| --- | --- | --- |
| 仿真 | Genesis、Franka、随机快递、双格口和 RGB-D | steps/s、并行环境数和任务录像 |
| 学习 | IK 专家和 LeRobotDataset 写入接口 | 训练曲线、检查点和策略成功率 |
| 鲁棒性 | nominal、in-domain、unseen 三类场景 | 未见场景成功率、恢复率和掉落率 |
| 闭环 | 接触/抬升/释放验证、重试、力阈值和中止 | 首次成功率与失败恢复成功率 |
| GPU 优化 | 并行环境扫描、批量执行接口、ROCm 快照 | 延迟、吞吐、显存和利用率 |
| 多模态 | RGB、Depth、关节、末端状态和接触力模式 | 状态/RGB/RGB-D 消融实验 |

## 已实现的数据流

每个控制帧包含：

- 九维 Franka 关节位置
- 七维末端位姿
- 七维快递位姿，单独保存为 `observation.privileged_state`，仅专家和评估使用
- 三维目标格口位置
- 夹爪接触力
- 八维动作：末端位置、四元数和夹爪命令
- 任务文本
- 可选 RGB 与 Depth

快递真值位姿用于生成专家示范，不应作为最终视觉策略的推理输入。训练时可以从 `observation.state` 中删除真值字段，或通过视觉编码器替换它。

## 频率与数值约定

- 物理仿真：240 Hz，FP32
- 控制闭环：30 Hz
- RGB-D：10 Hz
- 学习策略动作：末端笛卡尔目标，不是原始力矩
- GPU：正式结果仅允许单张 Radeon；PyTorch 中设备名仍为 `cuda:0`

图像低于控制频率时，数据集保持最近一帧图像。后续若模型需要严格时间同步，应在训练预处理阶段使用时间戳重采样。

## GPU 到账后的执行顺序

1. 运行 ROCm 预检和 Genesis 冒烟测试。
2. 用 nominal 场景校准抓取高度、夹爪力和控制增益。
3. 确认左右格口、失败重试、释放和 MP4 均正常。
4. 执行 in-domain 和 unseen 鲁棒性测试。
5. 采集成功的 RGB-D LeRobotDataset 专家回合。
6. 训练 ACT 或行为克隆并接入 `CartesianAction`。
7. 扫描并行环境数量、图像批量和推理精度。
8. 保存原始日志、完整配置、随机种子和硬件信息。

## 优化原则

- 物理求解和底层控制先保持 FP32。
- RGB-D 频率低于物理和控制频率。
- 学习策略推理时尽量避免 GPU 与 CPU 之间反复复制。
- 图像预处理与策略推理采用批量执行。
- 混合精度只用于经过稳定性对比的视觉模型推理或训练。
- 并行环境基准和真实任务成功率必须分开报告。
- 不将 RTX 5060 Ti 的 CUDA 数据冒充为 Radeon/ROCm 成绩。
