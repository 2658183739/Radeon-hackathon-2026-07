# 移动 SmolVLA RGB-D 消融

## 问题与配对协议

本实验检验：把已经采集的米制深度真正输入移动 SmolVLA 后，收益是否足以授权闭环评测。RGB v3
与 RGB-D v1 使用相同的七个专家回合、4,557 帧、任务文本、43 维非特权状态、19 维动作、种子 11、
AMP、batch 8、四个 worker、2,800 次更新、冻结视觉编码器和 expert-only 训练。RGB-D 只通过上游
SmolVLA 多图像接口增加 `observation.images.overhead_depth_rgb`；原始米制 TIFF 仍是深度来源记录。

RGB-D 数据审计覆盖全部状态、动作和任务阶段，并分布式检查 65 对深度图。所有三通道深度图均与
米制源数据的确定性编码完全一致。策略输入不包含包裹真值位姿。

## 单 Radeon 训练

训练在单张 AMD Radeon `gfx1100`、ROCm 7.2.1 和 PyTorch 2.9.1+ROCm 上完成。

| 指标 | RGB v3 | RGB-D v1 |
| --- | ---: | ---: |
| 更新 / epoch | 2,800 / 4.92 | 2,800 / 4.92 |
| 训练时间 | 约 7分20秒 | 8分51秒 |
| 稳态吞吐 | 约 63 samples/s | 约 43 samples/s |
| 峰值显存 | 2.21 GB | 2.75 GB |
| 末步 loss | 0.037 | 0.038 |

第二视觉流使训练时间增加约 20.7%、峰值显存增加约 24.4%、稳态吞吐下降约 31.7%，但仍只使用
47.98 GiB Radeon 显存的不到 6%。

## 配对 42 阶段结果

两个 checkpoint 使用完全相同的 episode、stage、frame 和 seed，并在每个样本前重置策略队列。

| 可执行路径 | RGB 平均 MAE | RGB-D 平均 MAE | RGB-D 变化 | RGB / RGB-D 包络 |
| --- | ---: | ---: | ---: | ---: |
| 原始 SmolVLA | 0.019790 | 0.020097 | +1.55% | 0/42 / 0/42 |
| 安全限幅 | 0.020893 | 0.020955 | +0.30% | 42/42 / 42/42 |
| Harness-Lite | 0.005370 | 0.005442 | +1.35% | 42/42 / 42/42 |

离线平均推理延迟从 145.63 ms 增至 159.69 ms（+9.65%）。预注册门要求 Harness 配对误差改善、
安全包络不回归且延迟增长不超过 25%。RGB-D 通过安全与延迟检查，但没有改善误差，因此决策为
`rgb_retained`，不授权执行 100 回合 RGB-D campaign。

## 在线集成检查

仅使用一个已知开发纸箱验证在线双图链路。它完成抓取、30 cm 运输、放置和释放，共进行 68 次
RGB-D 推理，VLA 实际控制 3,410 个物理步；峰值接触力 7.70 N、无紧急停止，热推理平均 211.44 ms。
该单个开发回合不是成功率或泛化结果。

## 结论

当前实现证明了 ROCm 上真实的 RGB-D 训练与在线推理，但顶视深度对小规模、视觉简单的训练总体没有
增加有效信息。后续深度研究应重新冻结“视觉歧义”数据集，覆盖外观相似但高度不同、遮挡、杂乱和
透明/低纹理代理物体；不能继续用本次 42 个样本调参，也不能把“增加模态”直接写成能力提升。

紧凑证据位于 `evidence/mobile_bimanual/rgbd_v1/`；907 MB 模型保留在 Radeon 主机，并由
`checkpoint-SHA256SUMS` 绑定。
