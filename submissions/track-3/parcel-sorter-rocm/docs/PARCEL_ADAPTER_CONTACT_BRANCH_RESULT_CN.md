# 包裹适配器接触分支结果

## 结果

预注册诊断成功把质量感知适配器的稳定回归定位到高频数值接触分支，但唯一预注册的约束时间候选没有修复问题。实验没有调整任务参数、控制增益、力阈值、密度、适配器长度、摩擦、抓取候选，也没有打开新 episode 或 holdout。

这是 `medium_carton / 4120001 / canonical-long-+0.000-up-0.045` 的有界开发结果，不代表鲁棒性或整个仿真器的普遍结论。

## 差分诊断

两个条件使用相同的 30 mm 适配器碰撞几何、1240 kg/m3 密度声明、控制器、轨迹、240 Hz 物理频率、30 Hz 控制频率和实测 35 N 中止。初始唯一差异是是否把适配器质量、质心和完整惯量合并到每根手指。

| 信号 | 原装惯量几何消融 | 合并质量感知惯量 |
|---|---:|---:|
| 任务结果 | 成功 | 安全中止 |
| 控制帧峰值力 | 12.547963 N | 38.336445 N |
| 首次接触身份差异 | 参考点 | 197/2 |
| 首次力差超过 1 N | 参考点 | 197/4 |
| 首次手指位置差超过 0.1 mm | 参考点 | 202/0 |
| 首次失去双侧支撑 | 无 | 对齐比较中的 203/5 |
| 高频峰值力 | 10.909115 N | 162.186157 N |
| 高频最大穿透 | 小于 1 mm | 115.545757 mm |
| 手指最大绝对速度 | 小于 0.01 m/s | 2.585403 / 2.414580 m/s |
| 手指最大绝对实际力 | 0.076706 / 0.072491 N | 78.010399 / 72.132576 N |
| 手指最大绝对控制器力 | 20 / 20 N | 20 / 20 N |

最早的分支很小：在 197/2，轻量条件多出第 9 个原装指尖接触，质量感知条件仍是 8 个接触，此时控制命令完全相同。质量感知轨迹表面上保持对称直到 203/3；仅过一个 1/240 秒子步，`left_finger/stock_finger_collision_3 <-> parcel` 就报告 115.5 mm 穿透和 162.19 N。手指速度与实际力在同一子步跳变，而控制器命令没有变化。适配器碰撞体只在失稳后出现，并非峰值接触。

证据支持以下先后关系：

1. 惯量改变了原装指尖的离散接触分支；
2. 微小力差在可测手指位置分叉前逐步累积；
3. 接触求解产生非物理穿透和力冲击；
4. 手指状态与实际内部力在冲击后分叉；
5. 未修改的 35 N 监控器正确中止运行。

证据不支持把峰值归因于 VLA、抓取选择器、高层控制器或适配器盒体直接碰撞。

## 冻结约束时间实验

Panda MJCF 的双指 equality 使用 `solref="0.005 1"`；Genesis 还会提示，在 240 Hz 下某个 `0.005 s` 约束时间常数会被提高到 `0.008333 s`。执行前只预注册了一个候选：仅把适配器资产的 equality 时间常数改为 Genesis 文档默认值 `0.010 s`，阻尼比仍为 1，其他运行与任务值全部不变。

第一次设置核验只修改了生成的适配器文件。环境创建时立即用 Genesis 源资产重新生成该文件，所以干预在两个场景构建前就被覆盖了。那条逐值相同的轨迹被归类为排除的无操作设置运行，不作为候选证据。

有效运行在命令作用域内先修改源资产，再执行生成。源 MJCF 和生成 MJCF 均确认是 `solref="0.010 1"`，此前的约束时间警告也消失了。候选随后更早、也更严重地失败：

- 实测力监控在控制帧 134 中止，而不是 204；
- 控制帧峰值升至 `105.85269165039062 N`；
- 终止运输阶段是 `raise`，早于原来的 `transfer` 失败；
- rollout 在冻结的 196--204 分支窗口前结束，因此正确记录为 0 个 contact-branch 样本，没有伪造高频证据。

运行结束后，源 MJCF 和生成 MJCF 均已恢复为 `0.005 s`。这个已确认生效的候选被否决，不进入正式配置。按照预注册停止规则，没有扫描其他约束时间，也没有打开其他 episode。

## 安全与工程决策

带真实质量的 30 mm 适配器仍是物理上诚实的模型，也是有价值的负基准；但 Genesis 1.2.3 当前求解设置下，已知 `+45 mm` 哨兵不具备部署条件。项目必须保留实测 35 N 中止，也不能把原装惯量消融冒充成物理解法。

下一项允许的工程工作应面向上游：把遥测缩减成 Genesis 最小复现，确定究竟哪条求解约束产生警告，再在新的预注册下验证仿真器修复或有文档依据的求解选项。在此之前，VLA 微调、视觉模型变更和大规模鲁棒性评估都不能修复、也无法有效评估这个底层数值问题。
