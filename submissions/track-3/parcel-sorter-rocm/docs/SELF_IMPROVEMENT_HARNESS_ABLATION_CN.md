# 三吸盘、Harness-Lite 与自改进实验协议

## 目标与边界

本协议面向单张 AMD Radeon GPU、ROCm 和 Genesis 的固定 Panda 快递分拣任务。目标不是用单个成功轨迹宣称泛化，而是在冻结的五类核心包裹上取得至少 80/100 个未见回合成功，并报告 Wilson 95% 置信区间、接触力、端到端时延和失败类型。

五类核心包裹为 `small_carton`、`medium_carton`、`flat_mailer`、`upright_canister` 和 `mailing_tube`。每类 20 个回合，随机质量、摩擦、位姿、偏航、相机噪声和动作延迟；训练、开发和冻结确认 episode 不重叠。80% 是预注册的点估计门槛，不等于任何“顶尖机械臂 80%”的跨论文能力声明。

## 三吸盘末端

三只开源 MJCF 圆柱吸盘以等边三角形布置在 Panda 手部。每个杯半径 12 mm，阵列半径 25 mm，杯长度 12 mm。手部惯量通过平行轴定理与三只圆柱的质量/惯量合并，避免把末端附加质量忽略掉。

吸附遵循以下安全条件：

1. 包裹必须先产生真实 Genesis 碰撞接触。
2. 至少两只杯口在包裹局部顶面覆盖范围内，间隙不超过 8 mm，法向夹角不超过 0.25 rad。
3. 建立后，使用最大 30 N 的六维弹簧阻尼广义力，而非设置包裹位置或瞬移。
4. 相对位移大于 35 mm 或相对角度大于 0.70 rad 时立即断吸。
5. 原有 35 N 接触安全中止保持不变。

当前覆盖 `suction_required` 的刚性盒体/扁平邮件边界件。横放大型圆柱仍为 `cradle_required`，不把吸盘误写成圆柱托架的替代品。

### 已验证开发结果

2026-07-26，在单张 AMD Radeon `gfx1100`、ROCm 7.2、Genesis 1.2.3 上，`usps_flat_rate_envelope_proxy` 的固定开发回合成功：4.8 s、零重试、最大接触力 14.78 N、最大吸附合力 17.86 N、一次锁定、零次断吸。原始证据在云端 `outputs/tri-suction-envelope-dev-v3/catalog-evaluation.json`。这是 `1/1` 开发验证，不参与 100 回合泛化统计。

## Harness-Lite 决策层

Harness-Lite 不替换 SmolVLA，也不替换安全控制器。它在每一次慢速 VLA 更新时生成四个沿专家可行运动轴的候选残差（-0.5、0、0.5、1.0 倍），并以如下规则选择：

- VLA 残差上限为 1 cm；
- 每帧至少保留专家 50% 的推进；
- 接触力达到安全上限时回退专家动作；
- 记录候选数、回退次数、选择尺度和残差量。

这借鉴 `vla-eval` 的“模型一次适配、环境一次适配、统一可复现指标”思想，但本项目没有声称已完整接入 AllenAI 的框架，也没有引入其 CUDA Docker 镜像。参考：Choi et al., *vla-eval*, arXiv:2603.13966 (2026), Apache-2.0 仓库 `allenai/vla-evaluation-harness`。

## 自改进闭环

自改进采用隔离式、失败关闭的离线流程：

```text
冻结基线与保留集
  -> 运行仿真回合并保留视频/轨迹/安全事件
  -> 失败分型（力中止、掉落、接近超时、抓取验证失败等）
  -> 生成按严重度排序的 replay manifest
  -> 仅用开发失败样本进行数据再采集/微调
  -> 在相同冻结集评测候选
  -> 通过 80% + 改善 + Wilson 非劣性门禁才晋级，否则隔离/回滚
```

`scripts/build_self_improvement_cycle.py` 已自动生成 replay manifest 和候选晋级 JSON。它不允许把保留 episode 写回训练清单，也不在运行中替换生产检查点，因此当前属于“自动失败采集与受控离线再训练编排”，不是无监督在线改权重。

设计参考：

- Zhang and Shah, *VERITAS*, arXiv:2606.18247 (2026)：生成器-验证器在推理时筛选轨迹，再将验证轨迹用于离线策略改进。
- Hu et al., *ReCoVLA*, arXiv:2606.09630 (2026)：冻结基础 VLA，对失败状态训练残差恢复而不是直接重训整套基础策略。
- Lee et al., *Recursive Harness Self-Improvement*, arXiv:2607.15524 (2026)：Harness 同时是推理结构和高质量训练轨迹生成器；本项目只采用其可审计、少迭代、任务特定的思想，不复制其通用代理提示优化。

## 预注册消融

| ID | 变量 | 对照 | 主要回答的问题 |
|---|---|---|---|
| A0 | 纯专家 + 双指夹爪 | 当前专家 | 物理与安全基线 |
| A1 | 原始 SmolVLA | A0 | 端到端策略是否改善任务 |
| A2 | Slow-Fast VLA | A1 | 快速安全控制是否降低力和超时 |
| A3 | Harness-Lite | A2 | 多候选验证是否提高稳定性 |
| A4 | A3 + 失败 replay 微调 | A3 | 受控自改进是否改善冻结集 |
| A5 | A4 + 三吸盘 | A4 | 吸盘是否扩展扁平/大盒覆盖 |
| A6 | A5，无几何密封门 | A5 | 至少两杯密封门是否必要 |
| A7 | A5，无吸附力上限 | A5 | 30 N 上限是否必要 |

每个正式单元在五类核心包裹各 20 回合运行；扁平/大盒吸盘边界扩展集单独报告，不能混入核心成功率。每个关键比较至少三种随机种子，并保持 episode 清单和训练预算一致。

## 评分对应

- 机器人能力：以冻结 100 回合成功率、接触力和失败类型为主，不以开发样本代替。
- AMD/ROCm：Genesis 物理、三吸盘接触/吸附、SmolVLA 推理、训练和评测均固定在单张 Radeon 上；记录 GPU、HIP、模型延迟和显存。
- 创新性：安全受限三吸盘、Harness-Lite 候选验证、失败分型和检查点晋级门形成一条可消融闭环。
- 应用价值：覆盖纸箱、扁平邮件和分类箱投放的快递小件分拣流程。
- 上游开源：尚未产生上游 PR，不能计入已得分；后续应把 Genesis/ROCm 的吸盘接触发现、ROCm 复现脚本或 LeRobot 适配问题整理为可审查贡献。

## 当前状态

三吸盘资产、密封门、力控制、Harness-Lite 和 replay/promotion 代码已实现并通过针对性单测。三吸盘已完成一个 Radeon 开发成功回合。100 回合冻结评测、多 seed、失败 replay 微调、Harness 对照和任何 80% 成功率声明尚未完成。
