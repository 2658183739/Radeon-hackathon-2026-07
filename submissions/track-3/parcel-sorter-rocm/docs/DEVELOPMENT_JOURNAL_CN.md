# 开发与实验日志

## 前言

本文记录可审计的工程过程，不是隐藏思维链的逐字转录。每条记录给出问题、当时证据、
备选方案、决策原因、代码变化、验证结果和是否保留。这样既便于学习，也符合 ADR、实验
追踪和可复现研究的常用规范。

状态含义：

- **已验证：**在目标 Radeon/ROCm 实例产生了代码、测试或闭环证据；
- **已实现待正式实验：**代码入口存在，但不能宣称模型或能力结果；
- **已拒绝：**实测不如基线，代码最多保留为可复现实验参数；
- **待做：**只有方案，不计入当前能力。

## 2026-07-24：包裹目录与控制优化

### 记录 1：从单一方盒扩展到明确的包裹目录

**问题：**原随机化只有一个基础方盒按比例缩放，无法回答系统对扁盒、长盒、圆筒和夹爪
边界包裹的表现。

**证据：**比赛按机器人任务效果与现实应用价值评分；一个混合总成功率会掩盖形状失败。

**备选：**继续宽范围连续随机；为每个物体写独立场景；使用带权 profile 目录。

**决策与原因：**采用带权 profile。7 个训练 profile 的权重在每 20 回合中精确分配，
另设 4 个行业尺寸 profile 只用于能力边界评测。这样兼顾训练分布、分层报告与重放。

**代码能力：**`ParcelProfileConfig` 校验形状、方向、处理类别、尺寸、质量、摩擦、权重和
来源；`DomainRandomizer` 提供稳定 block 调度和 `sample_profile()` 定点复放；
`evaluate_catalog.py` 支持重复 `--profile` 过滤且维持稳定 episode 编号。

**验证：**目录、调度、真实尺寸隔离、圆筒几何和未知 profile 共 5 类目录测试纳入 48 项
单元测试并通过。

**状态：**已验证，保留。

### 记录 2：增加 Box 与 Cylinder 物理几何

**问题：**把所有快递都模拟成 Box 会让“圆筒能力”成为错误声明。

**证据：**直立罐和横向邮筒的接触法线、滚动趋势与抓取轴不同。

**决策与原因：**在 `parcel_spawn_spec()` 中把 profile 映射为 Genesis Box/Cylinder。
横向邮筒绕 Y 轴旋转 90 度，初始高度由半径决定；直立圆筒高度沿 Z 轴。

**代码能力：**几何映射是纯函数，可脱离 GPU 单测；环境只消费经过验证的 spawn spec。

**状态：**已验证，保留。

### 记录 3：第一次完整目录烟雾测试

**问题：**新几何能生成不代表机器人能完成任务。

**证据：**第一次在 Radeon 上逐 profile 运行时，7 个训练 profile 全部失败。

**判断：**先检查控制与安全诊断，不能把失败归咎于“模型不够大”。

**代码能力：**每帧轨迹增加接触力、末端位置、包裹位置、预抓取/接触/抬升标志和力中止
标志，使失败能定位到 approach、grasp、lift、transfer 或 abort。

**状态：**诊断链路已验证。

### 记录 4：拆分水平接近与最终位姿容差

**问题：**一个 `position_tolerance_m` 同时控制 XY 对齐和三维到位，容易在高度尚不正确时
切换阶段，也会在阈值附近振荡。

**备选：**统一扩大容差；统一缩小容差；分离 XY 容差并给最终下降加滞回。

**决策与原因：**新增 `approach_xy_tolerance_m=0.015`；一旦水平对齐后进入最终下降，就锁定
该阶段，避免数值噪声反复退出。

**验证：**增加 XY 容差与滞回单测。`small_carton`、`flat_box`、`long_box` 和
`near_limit_box` 随后能完成单回合烟雾任务。

**状态：**已验证，保留。

### 记录 5：按几何调整预抓取窗口

**问题：**大盒因质心、末端和接触几何误差在严格 25 mm 窗口外停住；扁平包裹若使用同样
宽窗口又会过早下降。

**决策与原因：**较大的非扁盒使用 35 mm 窗口，扁平包裹维持 10 mm 精细窗口。窗口由
几何属性计算，不按 profile 名称硬编码。

**验证：**新增自适应容差测试；大盒烟雾运行成功，扁盒保持低接触力。

**状态：**已验证，保留。

### 记录 6：把斜线搬运改为三段式安全路径

**问题：**抓取后直接沿斜线去格口会让包裹过早接近桌面或格口边缘。

**备选：**提高格口目标；全程笛卡尔直线；先竖直抬升、水平搬运、再竖直下降。

**决策与原因：**采用三段式路径。它保持明确净空，诊断也能区分 lift、transfer、descend。

**验证：**盒类 profile 的完成路径和峰值接触力改善；相应动作目标加入单元测试。

**状态：**已验证，保留。

### 记录 7：圆筒抓取方向实验

**问题：**横向邮筒沿长轴夹取会碰撞，垂直长轴夹取又可能抬升时脱落；直立罐需要兼顾
指尖净空与双指接触。

**横筒 A/B：**把抓取 yaw 直接对齐生成 yaw 时达到 46.1 N 并中止，因此拒绝；恢复为与
圆筒轴垂直后峰值约 12.71 N，但仍在抬升中丢失。

**直立罐净空搜索：**额外净空 30 mm 时约 14 N 但无接触；15 mm 时约 27.3 N 仍无稳定
接触；8 mm 时约 29.3 N，仍未形成稳定双指接触。

**决策与原因：**保留 8 mm 和横筒垂直轴策略作为当前最安全几何基线，停止继续按单个
episode 手调。下一步应由更多圆筒数据、学习策略或末端执行器变更解决。

**状态：**安全改善已验证，任务能力仍是明确限制。

### 记录 8：20 秒最终目录烟雾结果

这只是每个训练 profile 一个固定 episode 的回归烟雾测试，不是正式成功率：

| Profile | 成功 | 终态 | 重试 | 峰值力 |
| --- | ---: | --- | ---: | ---: |
| `micro_box` | 否 | approach | 2 | 13.56 N |
| `small_carton` | 是 | complete | 0 | 10.71 N |
| `flat_box` | 是 | complete | 0 | 9.36 N |
| `long_box` | 是 | complete | 0 | 11.60 N |

**决策：**保留新的盒类控制与安全路径；把微型盒和圆筒放入困难样本队列，不把 4/7 写成
正式成功率。正式结论至少需要每 profile 多随机种子重复。

## 模型与视觉决策

### 记录 9：学习策略顺序

ACT 已跑通但闭环能力低于专家，因此先把它作为系统连通性基线。Diffusion 用于判断多峰
动作建模能否改善抓取；VLA-Adapter 0.5B 是通过许可证与 ROCm 门禁后的语言条件研究候选。
所有被接纳的策略都必须经过相同的监督器和安全执行链路，避免模型比较时改变控制系统。

### 记录 10：视觉输入边界

历史基线使用 RGB、20 维状态和接触力。修正后的新 shard 还提供确定性三通道深度视图，
ACT 训练、加载和推理接口烟雾已通过；能力结论仍需固定数据与 episode 的 RGB/RGB-D
匹配消融。任务文本只留给通过门禁的 VLA 候选。

### 记录 11：Diffusion 训练入口验证

第一次 1 步烟雾在数据切分后、模型创建前停止，原因是环境没有安装 LeRobot 的可选
`diffusers` 依赖。决策不是绕过错误，而是让 bootstrap 固定安装 `training,diffusion,smolvla`
extras，并在训练脚本中增加依赖预检。补装后，264M 参数 Diffusion 在 Radeon 上完成 1 次
前向、反向、优化器更新和检查点保存。该结果证明链路，不证明策略能力。

### 记录 12：SmolVLA 基座网络边界

依赖安装完成后，`lerobot/smolvla_base` 配置探针仍因实例无法连接 Hugging Face 失败。
因此脚本改为要求 `SMOLVLA_POLICY_PATH`：优先传入离线准备的本地开源检查点，只有网络
可用时才允许仓库 ID。后续检查点许可证审计取代了这一计划：该入口仅保留为历史兼容性
代码，不进入严格开源提交路径。

旧组合、手工复制配置，或增加均衡目录和确定性 profile 计划。**决策：**增加 12 类、精确
20 slot 的训练组合，并让采集/评测支持重复 `--profile`。承运商尺寸保持带来源、只评测。
**代码能力：**新增 `catalog_v2.toml`、`episode_plan.py`、按 profile 的专家/策略循环和覆盖
保护。**验证：**目录解析、精确权重、episode 命名空间、来源 URL 和拒绝覆盖均进入 Radeon
上的 56 项测试。**状态：契约级已实现和验证；尚未采集均衡数据。**

### 记录 14：ACT 与 Diffusion 受控变量

**证据：**多个模型选择原本硬编码，无法做匹配消融。读取固定 LeRobot 0.6.1 运行时配置后，

## 2026-07-24：catalog v2 证据驱动控制优化

### 记录 16：建立分层 catalog v2 基线

在单张 Radeon 上为 12 个训练 profile 各运行 1 个确定性 20 秒回合。`micro_box`、
`small_carton`、`flat_mailer`、`book_box`、`long_carton`、`upright_canister`、
`near_limit_box` 和 `electronics_box` 完成任务；中型纸箱与鞋盒代理触发 35 N 安全
边界，大型窄纸箱停留在接近阶段，邮筒在接近时滚走。这里的 8/12 只是十二个固定案例
的回归烟雾结果，不是成功率估计。**决策：保留为诊断基线；任何能力声明都必须等待
每类多回合评测。**

### 记录 17：拒绝两个高盒抓取候选

“高度感知”候选提高高包裹的预抓取高度，没有增加任何成功 profile。“闭合后落座”候选
也没有增加成功，三个目标盒的峰值力分别达到 51.10 N、51.64 N 和 48.33 N。两个候选
都未满足任务或安全验收条件。**决策：拒绝作为默认值并恢复原专家控制。**原始 JSON
轨迹保留在 `evidence/catalog/`，便于复现失败原因。

### 记录 18：把邮筒物理问题与抓取控制分开

基线邮筒在没有夹指接触时移动约 4.2 m，说明首先是物理建模问题。第一次开启 Genesis
滚动摩擦时，场景创建直接失败，因为 Genesis 1.2.3 要求启用滚动摩擦时同时启用扭转
摩擦。补齐两个 solver 选项并把邮筒滚动摩擦设为 0.002 后，短时漂移降到 18.3 mm，
但张开的夹爪发生 79.27 N 单指碰撞。

随后在同一 episode 上测试三个控制候选：最终接近步长 2.5 mm 仍以 36.74 N 中止；
2.0 mm 反而恶化到 98.83 N；5 mm 水平对齐阈值避免了碰撞，但机械臂追逐缓慢滚动的
邮筒直到 20 秒结束。这些 profile 级控制覆盖均已删除。把滚动摩擦提高到 0.005 后，
短时漂移降到 3.3 mm，但抓取仍以 73.99 N 中止。**决策：保留滚动阻力支持和 catalog
中的 0.005 物理候选，拒绝控制覆盖，并明确邮筒操作尚未解决。**下一步优先设计防滚
定位槽或改变末端执行器，不再围绕单个 episode 手调。

### 记录 19：当前优化顺序

1. 完成 solver 改动后的全目录回归；
2. 采集至少 300 个成功且类别均衡的 RGB-D 专家回合；
3. 用三个种子训练 ACT，按保留集闭环成功、再按安全和延迟选择检查点；
4. 使用相同数据切分与评测协议训练轻量 Diffusion；
5. 通过独立深度编码器加入深度，并完成 RGB 与 RGB-D 匹配消融；
6. 隔离审计 VLA-Adapter 0.5B 的递归许可证与 ROCm 算子；两项通过后才接入语义分拣
   目标选择，连续控制和安全仍放在下层；
7. 先 profile 仿真、渲染、主机到设备搬运和推理，再进行 ROCm 定向优化；
8. 等仿真器与策略契约稳定后再加入 ROS 2。

这个顺序先提升占分最高的机器人能力，同时保留可信的 ROCm、多模态、鲁棒性与部署路线。

### 记录 20：限定 Genesis 滚动 solver 的作用域

全局开启滚动和扭转摩擦后，目录烟雾从 8/12 降到 6/12，新增失败为 `micro_box` 和
`electronics_box`。逐 profile 对照表明它们与滚动物体无关。现在只有“横向圆筒且滚动
系数大于零”才开启两个 solver 选项；普通盒类和直立圆筒恢复原 solver 路径。Radeon 上
58 项测试通过，限定作用域后的完整目录重新得到基线一致的 8/12。**决策：保留限定作用域
的物理修正和回归证据，拒绝全局 solver 设置。**

## 2026-07-25：邮筒中心抓取与限定稳定等待

### 记录 21：调整控制前先修复圆筒采样

横向圆筒的半径和初始高度来自两个独立采样尺寸，固定邮筒样本因此在台面上方约 5 mm
出生。现在圆筒共享一个径向尺寸，生成高度使用构造基本体的同一半径。夹爪 yaw 也已修正，
使夹指长度沿邮筒轴线、闭合方向跨过直径。轴向修正把固定诊断峰值从 72.92 N 降到
43.54 N，但仍未通过安全线。**决策：保留两项几何修复，因为它们是在修正系统模型，而非
围绕无效状态调参。**

### 记录 22：按阶段设置接近、确认与抬升控制

邮筒 profile 现在支持 5 mm 最终接近和 10 mm 抬升步长，并要求连续三帧双指接触后再
抬升。固定诊断中，5 mm 接近以 34.26 N 通过接触门槛；稳定确认随后暴露了抬升滑移。
10 mm 抬升请求延长了接触，但仍在恢复阶段失败。**决策：把这些保留为限定作用域的接触
阶段变量，不把它们写成成功结论。**

### 记录 23：保留摩擦指垫与中心闭合位姿

把邮筒 profile 的指夹摩擦设为 2.0 后，峰值降到 15.62 N，三次尝试都进入抬升。轨迹
随后显示，通用 35 mm 圆筒容差会在目标上方约 33 mm 提前闭合。profile 使用 10 mm
容差后首次真正离台：邮筒中心从 30.9 mm 升到 66.4 mm，双指接触持续约 75 帧后滑落。
**决策：保留材料与位姿修正；邮筒仍按未解决的局部能力报告。**

### 记录 24：拒绝提高夹持力

25 N 和 35 N 的 profile 夹持力候选只把最高中心高度提高到 69.2 mm 和 69.9 mm，实测
峰值分别为 36.46 N 和 35.19 N，都越过冻结的 35 N 边界，也都没有完成抬升。正式代码
已经删除可选夹持力字段。**决策：拒绝；微小高度收益不值得安全退化和更大的配置面。**

### 记录 25：完整目录回归后限定稳定等待的作用域

全局三帧稳定等待使第一次完整回归从 8/12 降到 5/12；`flat_mailer`、`book_box` 和
`near_limit_box` 新增失败。稳定帧数现在是 profile 覆盖：全局一帧，邮筒三帧。Radeon
上 67 项测试通过，第二次完整回归恢复完全一致的逐 profile 8/12 结果。两份 JSON 都被

20 mm smoke 没有触发，因为最终下降前最小间隙约为 30.2 mm；40 mm smoke 触发 6 次，因此选择
40 mm 作为单个预注册候选，而不是无约束扫描。正式 A/B 触发 65 次，但成功从 1/20 降到 0/20，
力中止仍为 12/20，接近超时增加 1 次，并使 `7000005` 回归，所以拒绝候选。比较器现会聚合
守卫活动和计算开销，compact summary 省略逐帧轨迹时仍保留安全遥测。

验证包括本地 121 项测试、Radeon 116 项测试、shell 语法、固定比较、失败归因和本地/远端
SHA-256。结论是：实现谨慎且触发器能工作，并不等于安全控制有效；AABB 太粗糙，不能替代
有符号距离、接触感知低层控制或正确的恢复状态机。

### 记录 56：降低接近增益只是把力中止换成跟踪超时

本轮没有修改策略接口，而是实现按命令作用域切换机械臂增益：Kp 乘配置比例，Kv 乘该比例的平方根，
夹爪增益保持不变。环境只对延迟队列中真正执行的 `MOVE_PREGRASP` 动作切换增益，其它命令恢复名义
增益；默认值 1.0 因此严格复现历史控制器。

探针范围被有意限制。0.25 在没有接触的情况下超时，说明过度顺应会丢失跟踪能力；0.50 保留成功
回合 `7000005`，但第二个探针仍然超时，因此只把 0.50 提升为一次固定 A/B，而不是继续扫参数。
完整 Radeon 匹配结果中，力中止从 12 次降为 10 次，接近超时却从 7 次增为 9 次；成功仍为 1/20，
峰值力仍为 111.28 N，吞吐保留率只有 0.751。候选被拒绝，默认值继续为 1.0。

需要学习的关键点是：降低关节空间刚度不等于接触感知的笛卡尔阻抗控制。它可以降低部分测得的力，
同时减慢收敛并把失败从一种类别转移到另一种类别。下一项设计必须限制接触邻域内的笛卡尔接近速度
或能量，并显式定义恢复流程。验证包括 Radeon 123 项测试及 6 个 subtest、唯一配置差异比较、失败
归因、compact/full 哈希清单和完整运行日志。

### 记录 57：先证明速度接口，再依据任务证据拒绝控制器

编码前先检查已安装的 Genesis 源码，确认 Jacobian 的 0--2 行为平移、3--5 行为旋转。第一次
等权 DLS smoke 把过多控制能力用于旋转，因此只新增明确的 0.20 旋转权重，没有改动无关的状态机
容差。随后在 Radeon 上做隔离检查：机器人接受速度命令，实际关节速度达到约 1.03 rad/s，末端
下降约 25 mm，完整 API 链路得到证明。

集成 smoke 给出另一层证据：求解器预测约 -0.078 m/s 的垂直运动，但大纸箱旁的实际关节速度
停在约 0.005 rad/s。这指向手部/纸箱几何物理阻挡，而不是 Jacobian 方向错误或 ROCm 算子失效。
因此实现保留完整可观测性：请求和预测 twist、命令与实测关节速度、位姿误差、样本数和同步计算
耗时都会写入安全遥测。

固定 20+20 A/B 拒绝候选：成功从 1 次降为 0 次，力中止从 12 次增为 13 次，吞吐从每小时
17.80 件降为 0。P95 力虽下降，最大力未降，且 `7000005` 回归，因此默认继续关闭。验证包括
Radeon 正式测试 128 项及 6 个 subtest、shell 语法、comparison、两份失败归因、日志和本地/远端
哈希。下一轮应先表达可行的手部/纸箱几何与恢复状态，再调整连续控制器。

### 记录 58：再次修改控制器前，先诊断初始化碰撞

我增加了延迟 settle 的诊断入口，使场景能在普通初始化稳定过程之前，逐个检查 240 Hz 物理子步。
脚本记录双向 geometry/link 映射、接触力、位姿和精确的首次接触子步。结果证明 `7000001` 并非
首先在接近阶段失败：它的 hand 在第 0 子步已经与纸箱相交，产生约 1.27 kN 接触力；成功对照
`7000005` 从无碰撞状态开始。这份证据把下一实验从“继续调控制器”改成“检查 reset 可行性”。

实现会在积分前调用 Genesis `detect_collision()`，把无序碰撞对过滤到机器人/纸箱几何范围，并且
只在发生碰撞时选择固定后备 qpos。第二次查询是强制后置条件；若仍有碰撞则直接报错，不能静默开始
回合。功能默认关闭，比较器记录检查回合数、后备次数、切换前后碰撞对数量和计算耗时。

固定 20+20 Radeon 结果恢复 4 个旧失败，没有造成成功回归，但最终仍只有 5/20 成功和 8/20
力中止。这是有价值的根因干预，不是发布候选。因此保留代码和证据以便复现，同时继续默认关闭。
验证包括 Radeon 134 项测试及 6 个 subtest、两份逐子步诊断、精确配置 A/B、失败归因、日志、
compact summary 和本地/远端哈希。

### 记录 59：用顺序探针拒绝一个看似合理的容差修复

轨迹检查显示清晰模式：7 个高纸箱超时都已在 XY 基本居中，只是停在名义 hand 位姿上方
`40--50 mm`。我没有直接运行 40 个回合，而是实现默认关闭的几何接触判定，并把最便宜的证伪放在
最前面。判定分离水平与竖直可行性，上方接触带由纸箱高度、最小侧面重叠和硬上限共同决定。

v1 证明混合控制器对事件时序非常敏感：低纸箱窗口只扩大约 `2 mm`，闭合就提前一个控制帧，已知
成功变成力中止。随后把规则隔离到此前已经识别出的高纸箱分层；它保住已知成功，却把目标超时变成
更危险的抓取/重试中止。预先声明的停止规则因此在第三探针前结束实验。

代码继续默认关闭，因为负实验对教学和复现仍有价值。关键教训是：状态判定不能修复运动学不可行；
位姿生成器、碰撞检查和恢复转换必须对同一个物理稳定抓取保持一致。验证覆盖 Radeon 140 项测试及
6 个 subtest，并验证每个已执行探针的 compact/full 来源哈希。
