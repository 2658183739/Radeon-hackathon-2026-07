# 开发与实验日志

## 前言

本文记录可审计的工程过程，不是隐藏思维链的逐字转录。每条记录给出问题、当时证据、
备选方案、决策原因、代码变化、验证结果和是否保留。这样既便于学习，也符合 ADR、实验
追踪和可复现研究的常用规范。

状态含义：

- **已验证：**在目标 Radeon/ROCm 实例产生了代码、测试或闭环证据；
- **已实现待正式实验：**代码入口存在，但不能宣称模型或能力结果；
- **已拒绝：**实测不如基线，代码最多保留为可复现实验参数；
- **待做：**只有方案，不计入当前能力。

## 2026-07-24：包裹目录与控制优化

### 记录 1：从单一方盒扩展到明确的包裹目录

**问题：**原随机化只有一个基础方盒按比例缩放，无法回答系统对扁盒、长盒、圆筒和夹爪
边界包裹的表现。

**证据：**比赛按机器人任务效果与现实应用价值评分；一个混合总成功率会掩盖形状失败。

**备选：**继续宽范围连续随机；为每个物体写独立场景；使用带权 profile 目录。

**决策与原因：**采用带权 profile。7 个训练 profile 的权重在每 20 回合中精确分配，
另设 4 个行业尺寸 profile 只用于能力边界评测。这样兼顾训练分布、分层报告与重放。

**代码能力：**`ParcelProfileConfig` 校验形状、方向、处理类别、尺寸、质量、摩擦、权重和
来源；`DomainRandomizer` 提供稳定 block 调度和 `sample_profile()` 定点复放；
`evaluate_catalog.py` 支持重复 `--profile` 过滤且维持稳定 episode 编号。

**验证：**目录、调度、真实尺寸隔离、圆筒几何和未知 profile 共 5 类目录测试纳入 48 项
单元测试并通过。

**状态：**已验证，保留。

### 记录 2：增加 Box 与 Cylinder 物理几何

**问题：**把所有快递都模拟成 Box 会让“圆筒能力”成为错误声明。

**证据：**直立罐和横向邮筒的接触法线、滚动趋势与抓取轴不同。

**决策与原因：**在 `parcel_spawn_spec()` 中把 profile 映射为 Genesis Box/Cylinder。
横向邮筒绕 Y 轴旋转 90 度，初始高度由半径决定；直立圆筒高度沿 Z 轴。

**代码能力：**几何映射是纯函数，可脱离 GPU 单测；环境只消费经过验证的 spawn spec。

**状态：**已验证，保留。

### 记录 3：第一次完整目录烟雾测试

**问题：**新几何能生成不代表机器人能完成任务。

**证据：**第一次在 Radeon 上逐 profile 运行时，7 个训练 profile 全部失败。

**判断：**先检查控制与安全诊断，不能把失败归咎于“模型不够大”。

**代码能力：**每帧轨迹增加接触力、末端位置、包裹位置、预抓取/接触/抬升标志和力中止
标志，使失败能定位到 approach、grasp、lift、transfer 或 abort。

**状态：**诊断链路已验证。

### 记录 4：拆分水平接近与最终位姿容差

**问题：**一个 `position_tolerance_m` 同时控制 XY 对齐和三维到位，容易在高度尚不正确时
切换阶段，也会在阈值附近振荡。

**备选：**统一扩大容差；统一缩小容差；分离 XY 容差并给最终下降加滞回。

**决策与原因：**新增 `approach_xy_tolerance_m=0.015`；一旦水平对齐后进入最终下降，就锁定
该阶段，避免数值噪声反复退出。

**验证：**增加 XY 容差与滞回单测。`small_carton`、`flat_box`、`long_box` 和
`near_limit_box` 随后能完成单回合烟雾任务。

**状态：**已验证，保留。

### 记录 5：按几何调整预抓取窗口

**问题：**大盒因质心、末端和接触几何误差在严格 25 mm 窗口外停住；扁平包裹若使用同样
宽窗口又会过早下降。

**决策与原因：**较大的非扁盒使用 35 mm 窗口，扁平包裹维持 10 mm 精细窗口。窗口由
几何属性计算，不按 profile 名称硬编码。

**验证：**新增自适应容差测试；大盒烟雾运行成功，扁盒保持低接触力。

**状态：**已验证，保留。

### 记录 6：把斜线搬运改为三段式安全路径

**问题：**抓取后直接沿斜线去格口会让包裹过早接近桌面或格口边缘。

**备选：**提高格口目标；全程笛卡尔直线；先竖直抬升、水平搬运、再竖直下降。

**决策与原因：**采用三段式路径。它保持明确净空，诊断也能区分 lift、transfer、descend。

**验证：**盒类 profile 的完成路径和峰值接触力改善；相应动作目标加入单元测试。

**状态：**已验证，保留。

### 记录 7：圆筒抓取方向实验

**问题：**横向邮筒沿长轴夹取会碰撞，垂直长轴夹取又可能抬升时脱落；直立罐需要兼顾
指尖净空与双指接触。

**横筒 A/B：**把抓取 yaw 直接对齐生成 yaw 时达到 46.1 N 并中止，因此拒绝；恢复为与
圆筒轴垂直后峰值约 12.71 N，但仍在抬升中丢失。

**直立罐净空搜索：**额外净空 30 mm 时约 14 N 但无接触；15 mm 时约 27.3 N 仍无稳定
接触；8 mm 时约 29.3 N，仍未形成稳定双指接触。

**决策与原因：**保留 8 mm 和横筒垂直轴策略作为当前最安全几何基线，停止继续按单个
episode 手调。下一步应由更多圆筒数据、学习策略或末端执行器变更解决。

**状态：**安全改善已验证，任务能力仍是明确限制。

### 记录 8：20 秒最终目录烟雾结果

这只是每个训练 profile 一个固定 episode 的回归烟雾测试，不是正式成功率：

| Profile | 成功 | 终态 | 重试 | 峰值力 |
| --- | ---: | --- | ---: | ---: |
| `micro_box` | 否 | approach | 2 | 13.56 N |
| `small_carton` | 是 | complete | 0 | 10.71 N |
| `flat_box` | 是 | complete | 0 | 9.36 N |
| `long_box` | 是 | complete | 0 | 11.60 N |
| `upright_canister` | 否 | abort | 2 | 29.30 N |
| `mailing_tube` | 否 | abort | 2 | 12.71 N |

**决策：**保留新的盒类控制与安全路径；把微型盒和圆筒放入困难样本队列，不把 4/7 写成
正式成功率。正式结论至少需要每 profile 多随机种子重复。

## 模型与视觉决策

### 记录 9：学习策略顺序

ACT 已跑通但闭环能力低于专家，因此先把它作为系统连通性基线。Diffusion 用于判断多峰
动作建模能否改善抓取；SmolVLA 用于语言条件和轻量 VLA 展示。三者都必须经过相同的
监督器和安全执行链路，避免模型比较时改变控制系统。

### 记录 10：视觉输入边界

当前模型使用 RGB、20 维状态和接触力；SmolVLA还读取任务文本。深度虽然已按米保存，
但不能未经验证直接伪装成三通道 RGB。正确流程是定义独立深度编码/融合、固定数据与
episode 做消融，再决定是否保留。

### 记录 11：Diffusion 训练入口验证

第一次 1 步烟雾在数据切分后、模型创建前停止，原因是环境没有安装 LeRobot 的可选
`diffusers` 依赖。决策不是绕过错误，而是让 bootstrap 固定安装 `training,diffusion,smolvla`
extras，并在训练脚本中增加依赖预检。补装后，264M 参数 Diffusion 在 Radeon 上完成 1 次
前向、反向、优化器更新和检查点保存。该结果证明链路，不证明策略能力。

### 记录 12：SmolVLA 基座网络边界

依赖安装完成后，`lerobot/smolvla_base` 配置探针仍因实例无法连接 Hugging Face 失败。
因此脚本改为要求 `SMOLVLA_POLICY_PATH`：优先传入离线准备的本地开源检查点，只有网络
可用时才允许仓库 ID。SmolVLA 仍处于“入口就绪、基座未传入、未训练”状态。

## 下一次开发流程

1. 从一个可量化失败开始，不从模型名称开始；
2. 固定基线、episode 和安全门槛；
3. 一次只改变一个主要变量；
4. 先单测，再单 episode 烟雾，再多种子闭环；
5. 分开看成功、安全、延迟和吞吐；
6. 记录保留、拒绝或重复及其原因；
7. 代码、配置、证据和双语文档同一提交。
