# 包裹夹爪双指约束稳定性协议

## 目的

带真实质量与惯量的 30 mm 包裹适配器恢复了冻结的 `+40 mm` 样例，却把原本成功的 `+45 mm` 开发哨兵稳定地变成安全中止。预注册的 240 Hz 接触分支对照在不改变控制器的前提下定位到以下顺序：

- 两个条件最早在控制帧 197、物理子步 2 出现接触数量差异；
- 包裹接触力最早在 197/4 相差超过 1 N；
- 手指位置直到 202/0 才相差 0.1 mm；
- 质量感知条件在 203/4 突然出现 115.5 mm 穿透、162.19 N 原装指尖接触、约 2.5 m/s 手指速度，以及 78.01/72.13 N 手指实际力；
- 两个条件的手指控制命令始终都是 `[-20, -20] N`；
- 峰值接触是 `left_finger/stock_finger_collision_3 <-> parcel`，不是适配器碰撞体。

Panda MJCF 使用 `solref="0.005 1"` 耦合 `finger_joint1` 与 `finger_joint2`。Genesis 1.2.3 明确警告：在 240 Hz 下，这个时间常数小于 `2 * dt`，因此运行时会被强制改为临界值 `0.008333 s`。增加手指惯量后，双指约束正好工作在离散稳定性边界。本协议先验证这个机制，不调整控制器、模型或任务参数。

## 冻结干预

只允许一个候选：

- 将质量感知适配器资产的双指等式约束时间常数显式设为 `0.010 s`；
- 原始阻尼比 `1` 保持不变；
- 30 mm 几何和 1240 kg/m3 合并惯量保持不变；
- 240 Hz 物理频率、30 Hz 控制频率、原控制器和实测 35 N 安全中止保持不变。

`0.010 s` 是 Genesis 1.2.3 文档中的 `constraint_timeconst` 默认值，并且大于 `2 * dt = 0.008333 s`。该值不是根据运行结果扫描得到的。

## 固定样例

| 字段 | 冻结值 |
|---|---|
| 配置 | `configs/catalog_v2.toml` |
| Profile / episode | `medium_carton / 4120001` |
| 候选 | `canonical-long-+0.000-up-0.045` |
| 适配器 | 30 mm、1240 kg/m3、合并刚体惯量 |
| 运行环境 | 单张 Radeon `gfx1100`、ROCm 7.2、Genesis 1.2.3 |
| 频率 | 240 Hz 物理、30 Hz 控制 |
| 安全中止 | 实测包裹接触力大于 35 N |
| 执行次数 | 一个全新场景 rollout |

不得打开新 episode、holdout，也不得扫描密度、长度、摩擦、增益、力阈值、抓取候选、物理频率或约束时间常数。

## 必须记录的证据

候选须在控制帧 196 到 204 记录同一套 240 Hz 接触分支信号，并补充：

- 配置的双指约束时间常数与阻尼比；
- 任务结果和控制帧峰值接触力；
- 高频信号首次越过 35 N 的位置；
- 高频峰值接触的身份、力和穿透深度；
- 手指最大速度、实际力与控制器力；
- 原始产物字节数和 SHA-256；
- 运行时间与 GPU 身份。

## 决策规则

只有同时满足以下条件，才判定该机制候选通过开发哨兵：rollout 成功、无安全中止、所有记录值有限、高频最大穿透小于 1 mm，并且从未越过现有 35 N 门禁。单个哨兵通过只构成机制证据，不代表鲁棒性成立。

若失败，保留结果作为 Genesis 接触敏感性基准并停止，不扫描时间常数，也不削弱安全门禁。若通过，则把该设置实现为显式、带版本记录、默认关闭的适配器选项，补齐单元测试与来源记录，再运行已定义的回归检查。新 episode 或评分 holdout 仍须另行预注册。
