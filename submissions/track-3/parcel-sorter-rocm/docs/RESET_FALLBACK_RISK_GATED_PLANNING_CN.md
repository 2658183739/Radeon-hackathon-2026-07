# 复位后备风险门控抓取规划

## 为什么需要这个方法

均衡的 180 回合 Radeon 筛选已经拒绝对所有适用高盒启用几何规划。碰撞检查复位和完整规划均为
38/60 成功、15/60 力中止；每次规划平均耗时 5.57 秒，并使逐回合峰值力均值增加 1.65 N。
真正启用规划的回合中，它恢复了一个 `large_narrow_carton`，也使一个 `medium_carton` 回归。

有效差别不是另一个盒体尺寸阈值。成功恢复样例初始时机器人与包裹相交，必须使用已验证的后备复位
姿态；回归样例初始无碰撞，不需要这项干预。因此新方法使用首次动作前的实测事件作为保守风险门控。

## 启用规则

只有四个条件同时满足，规划器才启用：

```text
规划器启用 = 规划总开关
             AND 几何适用
             AND（门控关闭 OR 实际使用了后备复位）
```

本文候选启用门控，因此必须满足“实际使用了后备复位”。Genesis 在场景构建后、物理稳定等待前、
首次策略动作前查询机器人/包裹碰撞。如果历史复位与包裹相交，机器人切换到固定无碰撞后备姿态，
第二次查询必须得到 0 个跨实体碰撞对。若第二次查询仍失败，环境直接中止初始化，不会静默启用规划。

## 闭环接入

`GenesisParcelEnv` 先计算静态盒体适用性，并把规划初始化为关闭；完成场景构建和碰撞检查复位后，
再根据实测后备事件确定最终状态。公开属性 `geometry_grasp_planning_active` 同时控制 supervisor 的
稳定双指接触等待，因此未启用规划时不会改变历史状态机时序。

规划启用后，原规划器仍会生成相对盒体的位置和对称腕部姿态，检查 IK/FK 误差，在每个候选后恢复
状态，拒绝非夹指碰撞，按可操作度与关节行程排序，并在重试后重新规划。风险门控只决定是否进入这条
昂贵路径。

## 可审计遥测

每个回合记录：静态几何适用性、门控是否配置及满足、最终规划启用状态、后备复位前后碰撞对、规划
次数、选中候选、事件和同步计算耗时。配对比较报告进一步汇总几何适用回合、门控满足回合、实际启用
回合、门控避免规划回合，以及总规划耗时和单次耗时，从而直接量化延迟与 GPU 工作量节省。

## 复现

运行三个机制探针：

```bash
bash scripts/run_reset_fallback_gate_probes_rocm.sh
```

运行冻结的 120 回合验证：

```bash
bash scripts/run_reset_fallback_gate_campaign_rocm.sh
```

验证覆盖 12 个支持 profile，每个 profile 使用 5 个全新局部 episode，并比较两组严格配对方法。
`120000`--`120004` 是开发验证命名空间，最终确认范围 `200000`--`200039` 继续保持未查看。

## 初始 Radeon 机制证据

三个机制探针均在单张 Radeon 与 ROCm 上通过：

| Episode | 后备复位 | 规划器 | 结果 | 峰值力 |
|---|---:|---:|---:|---:|
| `4100004 medium_carton` | 否 | 未启用，0 次 | 成功 | 6.05 N |
| `7100002 large_narrow_carton` | 是 | 启用，1 次 | 成功 | 9.23 N |
| `1100000 small_carton` | 否 | 未启用，0 次 | 成功 | 7.18 N |

这些探针只验证机制并保留一个已知恢复，不构成性能声明。此前轨迹审计已发现规划器未启用时也可能发生
Genesis/GPU 状态分叉，因此必须等待配对验证 campaign，并补充同条件执行重复。
