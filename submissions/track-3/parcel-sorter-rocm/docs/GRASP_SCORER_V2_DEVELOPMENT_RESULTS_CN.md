# 抓取评分器 V2：Development 晋级结果

## 决策

V2 的一次性 development 评测结果为 `no_promotion`。pointwise 和
groupwise-safety-first 都未通过预注册门禁，没有模型被选中，holdout 未打开。运行时继续使用静态
几何排序基线，V2 development 不得再用于调参或二次选模。

16 个 development 组和 96 次候选闭环执行全部完成，四个 profile 各 4 组，0 组采集失败。评测前
独立验证两份冻结检查点哈希未变化，评测后验证决策、数据集和两份评测文件 SHA-256 一致。

## 门禁结果

| 方法 | 成功 | 安全中止 | 平均峰值力 | 六候选 warm P95 | 结论 |
| --- | ---: | ---: | ---: | ---: | --- |
| 静态几何基线 | 9/16 | 4/16 | 36.10 N | N/A | 当前默认 |
| pointwise | 6/16 | 9/16 | 134.95 N | 0.909 ms | 拒绝 |
| groupwise-safety-first | 7/16 | 8/16 | 125.88 N | 0.924 ms | 拒绝 |

两模型都满足 5 ms 延迟门槛，但四个 profile 全部发生安全中止回归，并且总体既没有任务改善也没有
安全改善。速度指标不能覆盖安全和任务失败。

## 失败归因

训练阶段的 192 行数据对应 32 个独立物理组，而网络有 6,276 个参数；两个目标都把训练损失降到
接近零。到了 development，pointwise 在 13/16 组偏离静态首选，groupwise 在 12/16 组偏离，且
经常选中高静态 rank 候选。实际安全中止候选的平均峰值力分别是 222.15 N 和 229.79 N，模型预测
均值却只有 21.53 N 和 26.69 N。

最严重的 `medium_carton:8410034` 候选达到 1,489.78 N，groupwise 只预测 23.74 N 和
0.000155 的不安全概率。96 条 development 候选中只有 14 条使用全局未见候选 ID，两模型各只选中
2 条，因此失败不能只归因于离散 ID 未见；更主要的是训练组太少、接触动力学尖峰不连续、静态特征
缺少可校准的动态风险信息。

## 候选集合是否仍有价值

事后 oracle 只用于诊断，不是可部署算法：16 组中 15 组至少有一个安全候选，13 组存在安全成功
候选，只有 1 组全部危险。安全优先 oracle 的上界是 13/16 成功、1/16 安全中止，明显好于静态
基线 9/4。这说明候选生成仍有提升空间；被否决的是 V2 学习排序器，而不是机械臂或候选集合。

## 下一研究边界

V2 到此关闭，不能在同一 development 上增加阈值、改损失或再选模型。新的 V3 若继续排序学习，
必须在任何新物理结果前冻结全新且互不重叠的 train/development/holdout，总体应扩大物理组数量，
使用 train 内交叉验证完成容量和校准选择，并加入不确定性/OOD 拒绝与静态基线回退。相对几何特征
和短时动态接触探针可作为新假设，但必须用新总体验证。

机器可读证据见 `evidence/training/grasp-scorer-v2-development-evidence.json`。
