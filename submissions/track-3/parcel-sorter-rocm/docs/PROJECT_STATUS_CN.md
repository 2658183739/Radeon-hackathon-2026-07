直到补齐均衡采集、通过相同审计，并冻结新的拆分清单。

将成功从 1/20 提升到 4/20，并提高吞吐，但仍有 9/20 次力中止且使一个基线成功回合退化。

同一张 Radeon 已对完成的 400 回合审计清单运行 `plan_balanced_collection.py`。它为新的独立

## 硬性约束

- 只使用一张 AMD Radeon GPU，并确保进程只看到一个设备；PyTorch 必须走 ROCm/HIP。
- 仿真器、代码、模型实现和数据必须开源或具备可审计的合法使用许可。
- 竞赛路径中的物理仿真、渲染、训练、推理和 benchmark 均在同一张 Radeon 上完成。
- 所有模型比较都要在选模前固定数据拆分、episode 编号、安全阈值、随机种子和产物哈希。

## 推荐执行顺序

```text
1. preflight_radeon.sh
2. 缺依赖时执行 bootstrap_radeon.sh
3. python -m unittest discover -s tests -q
4. run_expert.py --config configs/catalog_v2.toml --record-sensors --lerobot
5. audit_dataset.py --require-depth-rgb
6. 在相同拆分和三个种子上训练 RGB ACT 与 RGB-D ACT
7. 对固定留出 episode 清单执行 evaluate_policy.py
8. 执行 compare_expert_runs.py / summarize_act_evaluations.py
9. 运行轻量 Diffusion 的匹配对照
10. 打包源码、锁定文件、日志、指标和复现命令
```

已完成的 Radeon 采集只是数据生成产物，不是最终模型能力结论。数据已经完成审计，并按 profile
拆分 train、validation 和固定 held-out 集；5K 矩阵还必须通过留出集评测后，才能报告任何学习策略结果。

`scripts/build_dataset_split.py` 是复现边界：它把 audit 中的原始 episode ID 映射到 LeRobot
紧凑的成功回合索引，按包裹 profile 分层，并输出 ACT 与 Diffusion 共用的精确 episode 列表。
缺少 `summary.json`、metadata/计数不一致或多任务数据都会被主动拒绝。

watch_and_train_rocm.sh 可以等待采集 summary、生成清单并启动顺序 ACT 矩阵；未完成数据不会
触发训练，编排过程写入独立日志。

## 优化门禁

1. **数据门禁：**至少 300 个成功且按 profile 均衡的 RGB-D 回合；保存不可变清单和哈希。
2. **模型门禁：**RGB ACT、RGB-D ACT、轻量 Diffusion 使用相同拆分、三个种子和明确预算。
3. **任务门禁：**每个候选至少 30 个未参与选模的闭环回合，最终固定比较集至少 60 回合。
4. **安全门禁：**候选不得超过 35 N 接触力或增加掉落率；报告首次成功、恢复、掉落及分层结果。
5. **性能门禁：**在同一张 Radeon 上报告同步计时的平均/P95 延迟、samples/s、峰值显存和 GPU 利用率。
6. **扩展门禁：**VLA、吸盘、cradle、点云或 ROS 2 必须等前述门禁通过，并完成新增依赖/许可证审计。

## 最新均衡筛选：拒绝完整规划器

冻结的单张 Radeon campaign 已完成 12 个受支持 profile、共 180 个回合。碰撞检查复位与完整规划
均为 38/60 成功、15/60 力中止和 0 掉落。完整规划使逐回合峰值力均值增加 1.65 N，配对 Bootstrap

episode 外，还必须加入同条件执行重复。下一项开发候选只在检测到机器人/包裹初始碰撞、且确实触发

## 最新受控实验：拒绝复位后备风险门控

19/60 力中止、0 掉落。逐回合峰值力均值从 22.87 N 增加到 29.54 N，成功吞吐降至 0.910 倍。

候选只有 5 个回合实际启用规划，其中恢复 1 个、回归 2 个；另一个结果变化发生时规划次数为 0，

默认关闭，不会在预留确认编号 `200000`--`200039` 上评测。

当前最优先的可靠性工作，是对 4 个验证分叉回合做分块同 episode 重复。每个条件下的 5 次执行是
嵌套测量，不是独立包裹样本。正式学习策略排名、VLA 和 ROS 2 继续排在专家安全性与重复性闭环
之后。

重复性研究现已完成。两个规划回归和一个规划恢复均 5/5 重现。未启用规划的 episode 在两种方法下

独立的进程局部场景顺序效应。每次新进程的哨兵重复是剩余可靠性检查，但不能成为重新打开已拒绝

## 最新机制探针：拒绝规划抓取运输契约

`raise -> raise_settle -> transfer -> transfer_settle -> descend`。默认参数为 20 mm 抬升
参考步长、10 mm 运输参考步长和 2 帧阶段交接；有界前瞻仍受全局 40 mm 跟踪误差上限约束。
新增遥测记录运输阶段、动作目标、末端/包裹四元数和相对位置。35 N 安全阈值没有修改。

三个已观察开发回合只用于机制定位。阶段锁存使 `7120004` 从 69.00 N 失败变为 13.88 N 成功，
并最终保留 `5120003` 的 29.69 N 成功；但 `4120001` 在慢运输中滑落。为缩短运输加入的

默认关闭，不进入重复实验、普通 profile 哨兵或保留确认集。

当前优先级从统一运输步长调参转向抓取稳定性：负载感知抓取候选评分、侧抓姿态族，或检测滑移后
安全放回/重抓。任何下一轮性能声明都必须冻结新开发回合；均衡数据采集、正式学习策略排名、
VLA 和 ROS 2 仍受专家任务与安全门禁约束。完整证据见
`evidence/expert/radeon-transport-contract-probe-v1/`。

## 最新机理探针：拒绝纯夹力滑移恢复

在接入控制器前，静态筛选已经拒绝 stock Panda 的更深抓取：三组侧抓均没有可行候选，24 个倾斜

## 最新机理探针：拒绝动态短测排序与放回重抓

完整场景快照诊断在三个已观察开发 episode 上分别评估 6 个唯一静态可行抓取，每个重复两次。
场景恢复误差为 `0.0`，重复指标完全一致；但 30 mm 带载短运输让正式长运输中会失败的 `+40 mm`

状态型恢复候选在冻结的第 159 帧滑移后安全执行

下一次运输仍以 129.98 N 中止。

两个机制都继续默认关闭。不能从这些开发探针声明成功率、鲁棒性或模型收益。下一项有依据的方向是
采用许可证明确的新支撑几何，或做长时域带载稳定性规划；相邻高度、夹力和放回步长扫描全部停止。
完整证据见 `evidence/expert/radeon-dynamic-stability-setdown-probes-v1/`。
